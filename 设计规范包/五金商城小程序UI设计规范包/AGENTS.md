# 五金商城小程序 UI 开发规范

## 1. 怎么用本规范

本规范适用于 `Wujin-Mall-Mini`，技术栈为 uni-app、Vue 3、微信小程序。开发页面时先确定页面目标，再套用这里的视觉令牌、布局规则、组件规则和页面验收点。

页面内不要随意硬编码新主题。确需新增样式时，先判断能否归入 `design-tokens.json` 的语义层。

## 2. 产品气质

- 工业采购：信息可信、结构清楚、强调规格、供应能力、交期和溯源。
- 清爽高效：白底浅灰、少装饰、强搜索入口、重点信息可扫读。
- 轻量 B2B：移动端采购工作台，不做营销落地页，也不做 PC 后台密度。

## 3. 全局视觉系统

- 页面背景：白色或极浅灰，禁止大面积深色背景。
- 头部：主题黄色覆盖首屏顶部区域，参考生活服务类 App 的清晰头部组织方式，但保留五金工业表达。首页黄头禁止堆叠大标题和长说明，优先放定位、搜索、消息、扫码等可操作入口。
- 文字：主文字使用黑色/深灰，辅助说明使用中灰，禁止低对比灰字。
- 强调：按钮、选中态、关键数字、泳道状态使用品牌黄。
- 圆角：移动端卡片 16-20rpx，按钮 14-18rpx，底部导航 0-24rpx，避免过度软萌。
- 阴影：只用于悬浮头部、底部导航和重点卡片，强度轻。
- 图像：优先真实五金、工艺、材料、供应商场景。没有真实图时使用结构化图谱和工业线框，不用卡通插画替代。

## 4. 小程序布局规则

- 首屏顶部必须考虑微信状态栏和胶囊区域，黄头区域建议 `padding-top` 使用系统状态栏高度。
- 页面主内容使用 `24-28rpx` 横向留白，重要卡片保持稳定间距。
- 底部导航固定时，页面底部至少预留 `160rpx + safe-area`。
- 固定底部操作栏只放关键动作，例如提交寻源、发消息、查看进度。
- 触控热区不小于 `72rpx` 高，按钮文字必须单行可读。

## 5. 核心业务页面规则

- 首页搜索：顶部黄头包含定位、消息、扫码和搜索框；不要在黄头内放“产品介绍式”大标题和说明文案。三泳道入口、近期/热门搜索放在黄头下方内容区。
- 三泳道结果：成品、加工、原材料三列或三段并列展示，保留当前关键词和来源上下文。
- 详情页：顶部黄头说明当前对象，主体以规格、适配、风险提示、供应动作组织。
- 溯源图谱：必须展示成品、加工、原材料节点和关系路径，不只列文字。
- 一键寻源：先给供应商候选，再收集联系人、电话、需求说明，提交后能进线索进度。
- 供应能力：突出匹配度、主营能力、可承接泳道、响应/资质信息。
- 我的：定位为采购工作台，展示登录状态、线索、询价、收藏、沟通、设置。
- 消息：定位为供应沟通，使用 WukongIM 会话模型 `channelId/channelType`。

## 6. 信息组织规则

- 搜索上下文不得丢失：页面跳转需要保留 `keyword`、`lane`、`sourceKeyword`、`id`、`entityType`。
- 三泳道名称固定：成品 `PRODUCT`、加工 `PROCESS`、原材料 `MATERIAL`。
- 风险提示要说明“同名材料/工艺跨行业不可默认互换”。
- 空状态必须给下一步动作，例如继续搜索、发布寻源、联系客服。

## 7. 组件规范

- 搜索框：白底、黑字、黄色搜索按钮，放在黄头内。
- 泳道分段控件：三段稳定宽度，选中态黄色底或黄色边。
- 商品卡：标题、泳道、摘要、数量/匹配度、详情/溯源动作。
- 供应商卡：供应商名称、匹配度、主营、服务说明、能力详情。
- 风险提示：浅黄底、黑/棕文字、左侧小标识。
- 状态徽标：提交、匹配、响应、跟进四阶段，禁止只用颜色表达状态。
- 空状态：一句原因 + 一个下一步按钮。

## 8. 禁止清单

- 禁止继续使用论坛、校园、活动、帖子等主体验文案。
- 禁止大面积蓝绿渐变、卡通插画、娱乐化图标。
- 禁止页面内随机硬编码主题色。
- 禁止跳转详情、寻源、图谱时丢失关键词和泳道。
- 禁止“暂无数据”后不给操作。
- 禁止把 WukongIM 和旧 Tencent TUIKit helper 混写在同一个 service。

## 9. 自查清单

- 头部是否为主题黄，页面背景是否白/浅灰，主字是否黑/深灰。
- 页面是否保留搜索上下文和三泳道参数。
- 登录是否保留 `accessToken/refreshToken/expiresTime` 和刷新链路。
- 消息是否使用 WukongIM 的 `channelId/channelType` 路由。
- 底部导航是否只暴露五金、寻源、溯源、我的。
- 空态、错误态、加载态是否有下一步动作。
