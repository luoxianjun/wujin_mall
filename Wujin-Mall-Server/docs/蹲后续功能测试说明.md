# 蹲后续功能测试说明

## 功能概述

蹲后续功能允许用户关注帖子，当帖子有新评论或关注数达到特定阈值时，会收到系统通知。

## 功能实现

### 1. 评论通知

**触发条件**：
- 用户A蹲后续了帖子X
- 其他用户（非帖子作者、非被评论用户、非评论者本人）评论了帖子X

**通知内容**：
- 标题：`你蹲的帖子有新评论`
- 内容：`{评论者昵称} 评论了你蹲的帖子《{帖子标题}》`
- 通知类型：`FOLLOW` (类型3)
- 关联类型：`帖子` (类型1)

**实现位置**：
- `ForumCommentServiceImpl.addPostReplyUnread()` 方法
- 在 `ForumCommentServiceImpl.createComment()` 方法中调用

### 2. 关注提醒

**触发条件**：
- 帖子关注数达到 15、30、45、60... 等15的倍数时
- 通知所有已蹲后续该帖子的用户（排除当前关注者自己）

**通知内容**：
- 标题：`你蹲的帖子有{关注数}个新关注，快看看他们在聊什么吧`
- 内容：`你蹲的帖子《{帖子标题}》有{关注数}个新关注，快看看他们在聊什么吧`
- 通知类型：`FOLLOW` (类型3)
- 关联类型：`帖子` (类型1)

**实现位置**：
- `ForumPostServiceImpl.followPost()` 方法

## 测试步骤

### 测试评论通知

1. **准备测试环境**：
   - 准备至少3个用户账号（用户A、用户B、用户C）
   - 用户A发布一个帖子X
   - 用户B蹲后续帖子X

2. **测试步骤**：
   ```
   步骤1：用户C评论帖子X
   预期结果：
   - 用户B的"蹲后续"未读数增加
   - 用户B进入"消息-蹲后续"页面，能看到通知：
     * 标题：你蹲的帖子有新评论
     * 内容：用户C 评论了你蹲的帖子《帖子X的标题》
   ```

3. **验证点**：
   - ? 未读数量提醒正确显示
   - ? 点击进入"蹲后续"页面，能看到评论通知
   - ? 点击通知能跳转到帖子详情页

### 测试关注提醒

1. **准备测试环境**：
   - 准备多个用户账号（至少15个）
   - 用户A发布一个帖子X
   - 用户B蹲后续帖子X

2. **测试步骤**：
   ```
   步骤1：让14个用户关注帖子X（此时关注数为14）
   步骤2：第15个用户关注帖子X（关注数达到15）
   预期结果：
   - 用户B收到通知：
     * 标题：你蹲的帖子有15个新关注，快看看他们在聊什么吧
     * 内容：你蹲的帖子《帖子X的标题》有15个新关注，快看看他们在聊什么吧
   
   步骤3：继续让15个用户关注（关注数达到30）
   预期结果：
   - 用户B再次收到通知，标题显示30个新关注
   ```

3. **验证点**：
   - ? 关注数达到15的倍数时，正确发送通知
   - ? 通知标题和内容正确显示关注数量
   - ? 只有蹲后续的用户收到通知（当前关注者自己不会收到）

## 排查问题

### 问题1：有数量提醒，但点击进去后没有显示评论消息

**可能原因**：
1. 通知记录未正确创建
2. 查询时过滤条件有问题
3. 前端显示逻辑有问题

**排查步骤**：
1. 检查数据库 `forum_system_notice` 表：
   ```sql
   SELECT * FROM forum_system_notice 
   WHERE user_id = {用户B的ID} 
   AND notice_type = 3 
   ORDER BY create_time DESC;
   ```
   查看是否有 `title = '你蹲的帖子有新评论'` 的记录

2. 检查后端日志：
   - 查看是否有 `[addPostReplyUnread]` 的日志
   - 查看是否有 `[createSystemNotice]` 的日志

3. 检查前端请求：
   - 打开浏览器开发者工具
   - 查看 `/forum/message/notice/page?noticeType=3` 接口返回的数据
   - 确认返回的列表中是否包含评论通知

4. 检查用户是否真的蹲后续了帖子：
   ```sql
   SELECT * FROM forum_post_follow 
   WHERE post_id = {帖子ID} 
   AND user_id = {用户B的ID} 
   AND deleted = 0;
   ```

### 问题2：关注提醒没有发送

**排查步骤**：
1. 检查帖子关注数：
   ```sql
   SELECT follow_count FROM forum_post WHERE id = {帖子ID};
   ```

2. 检查是否达到15的倍数：
   - 关注数必须是 15、30、45、60... 等15的倍数才会触发

3. 检查后端日志：
   - 查看 `[followPost]` 方法的日志
   - 确认是否进入了发送通知的逻辑

## 数据库表结构

### forum_system_notice（系统通知表）
- `id`: 通知ID
- `user_id`: 接收人ID
- `notice_type`: 通知类型（3=关注通知）
- `title`: 通知标题
- `content`: 通知内容
- `related_id`: 关联业务ID（帖子ID）
- `related_type`: 关联业务类型（1=帖子）
- `read_status`: 是否已读

### forum_post_follow（帖子关注表）
- `post_id`: 帖子ID
- `user_id`: 用户ID
- `deleted`: 是否删除

## API接口

### 获取系统通知列表
```
GET /forum/message/notice/page
参数：
- noticeType: 3 (关注通知)
- pageNo: 页码
- pageSize: 每页数量
```

### 标记通知为已读
```
POST /forum/message/notice/mark-read
参数：
- noticeId: 通知ID
```
